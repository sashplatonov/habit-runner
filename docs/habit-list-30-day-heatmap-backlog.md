# Переработка списка привычек: хитмап за последние 30 дней — backlog реализации

## Цель

Каждый элемент списка привычек на dashboard должен показывать наглядный хитмап активности за последние 30 календарных дней, включая сегодня, в обоих режимах плотности: compact для мобильного списка и comfortable для desktop-плиток. Визуализация должна оставаться читаемой на мобильном экране и на ПК, не мешая основным действиям: отметить привычку и открыть её детали.

## Архитектурные решения

- Источник данных — существующее поле `Habit.completions`; новая история, API, DTO, миграция или локальное состояние не требуются.
- Для 30-дневного диапазона переиспользуется `MiniHeatmap.svelte`: он уже строит календарные даты через общие преобразователи completion key и интерпретирует выполнение относительно `dailyTarget`. Нельзя создавать второй расчёт дат или дублирующий компонент хитмапа в строке списка.
- Изменяются два представления одного dashboard-списка: `HabitCompactRow` для `compact` и `HabitTile` для `comfortable`. Полный `HabitHeatmap` на странице привычки, фильтрация, сортировка, drag-and-drop, свайпы и контракт отметки выполнения сохраняют поведение.
- Референс пользователя задаёт композицию: элемент управления и название в верхней части, 30-дневная сетка во всю полезную ширину внизу, дни от старого к новому слева направо. Цвет выполненной ячейки берётся из существующей темы привычки, невыполненная ячейка остаётся нейтральной.

## HLR-HEATMAP-01: Встроить 30-дневный хитмап в компактную строку привычки

**Status:** DONE
**Priority:** P1  
**Depends on:** —

**Точная область:**

Перестроить разметку `HabitCompactRow` в dashboard для плотного списка так, чтобы `MiniHeatmap` был постоянной нижней частью каждой строки, а не скрытым на экранах уже `md` правым показателем. Сохранить все существующие события строки и её интерактивные контролы.

**Файлы:**

- Изменить `apps/web/src/lib/components/dashboard/HabitCompactRow.svelte`.
- Использовать без изменения контракта `apps/web/src/lib/components/MiniHeatmap.svelte`.
- Контекст вызова: `HabitCompactRow` в `apps/web/src/routes/app/(protected)/dashboard/+page.svelte`.

**Цель:**

Пользователь видит в каждом элементе компактного списка непрерывную историю за 30 последних дней, в том числе на телефоне, как в приложенном референсе.

### Результат

В строке остаются кнопка выполнения, название и текущие краткие показатели, а ниже них размещается компактная календарная сетка из 30 дней. Она не обрезается, не появляется только на desktop и не перехватывает нажатие, которое должно открыть привычку.

### Архитектурное решение

Компонент строки отвечает только за расположение и доступное текстовое описание уже рассчитанного `MiniHeatmap`. Компонент хитмапа остаётся единственным местом, которое формирует диапазон, сопоставляет ключи дат и выбирает цвет по данным выполнения.

### Необходимые изменения

1. Перекомпоновать `HabitCompactRow` в вертикальную карточку: верхний ряд содержит существующий completion-control, кликабельную информацию о привычке и сохраняемые метрики; под ним — выделенная область хитмапа.
2. Показывать `MiniHeatmap` для каждого `HabitCompactRow` на всех целевых ширинах, передавая существующие `habit.completions`, `habit.dailyTarget` и `habit.color`; убрать только устаревшее условие скрытия на mobile, не изменяя смысл completion-данных.
3. Добавить неброские подписи границ диапазона, эквивалентные «30 days ago» и «today», либо доступное имя, сообщающее тот же диапазон. Не добавлять локализованный текст вне существующего механизма локализации: если эти подписи являются видимым UI-copy, завести их в используемом проектом i18n-ресурсе и использовать его.
4. Настроить flex/grid-ограничения так, чтобы длинное имя обрезалось как сейчас, а хитмап не вызывал горизонтальную прокрутку или наложение на completion-control, ring, tooltip, drag-grip и swipe-индикатор.
5. Не менять маршрутизацию `detail`, обработчики toggle/drag/swipe, правила completion, данные привычки и существующие desktop-плитки.

### Вне области задачи

- Изменение API, Java-сервиса, БД, Flyway-миграций или формата `Habit`.
- Добавление редактирования истории из хитмапа, tooltip для каждой ячейки или аналитики за период.
- Редизайн `HabitTile.svelte` в комфортной плотности и полного heatmap на странице привычки.
- Изменение сортировки, фильтров, тегов, freeze days либо механики streak.

### Критерии приёмки

- В compact-режиме dashboard каждая видимая привычка отображает сетку ровно за 30 календарных дней: первый день — 29 дней до сегодня, последний — сегодня.
- Значение completion не меньше `dailyTarget` окрашивает соответствующую ячейку цветом темы привычки; пустое или неполное значение остаётся нейтральным. Расчёт использует существующее canonical completion-key преобразование.
- На ширине 320 px карточка и её хитмап полностью помещаются в viewport без горизонтальной прокрутки, перекрытий и потери 44×44 px completion-control.
- На ширинах mobile и desktop хитмап не исчезает из DOM из-за breakpoint-класса; длинное название не выталкивает его за границу карточки.
- Клавиатурой можно по-прежнему сфокусировать и активировать кнопку отметки и кнопку открытия деталей; ячейки визуализации не создают лишних tab-stop.
- Drag-and-drop и swipe-action продолжают работать с целой карточкой, а клик по информационной части по-прежнему открывает детали привычки.

## HLR-HEATMAP-02: Добавить 30-дневный хитмап в desktop-плитку привычки

**Status:** DONE
**Priority:** P1  
**Depends on:** —

**Точная область:**

Заменить компактный 90-дневный `HabitHeatmap` в нижней части `HabitTile` на тот же 30-дневный визуальный сигнал, что используется для compact-строки. Сохранить карту-слот, ring, tooltip, переход к деталям и прямую отметку выполнения.

**Файлы:**

- Изменить `apps/web/src/lib/components/HabitTile.svelte`.
- Использовать без изменения контракта `apps/web/src/lib/components/MiniHeatmap.svelte`.
- Контекст вызова: ветка `viewDensity === 'comfortable'` в `apps/web/src/routes/app/(protected)/dashboard/+page.svelte`.

**Цель:**

На desktop dashboard каждая плитка привычки показывает компактный 30-дневный хитмап, согласованный с мобильным compact-представлением и референсом пользователя.

### Результат

При comfortable-плотности нижняя часть плитки содержит 30-дневный heatmap с понятными границами периода. Сетка использует полезную ширину плитки, но не уменьшает и не перекрывает 44×44 px кнопку выполнения.

### Архитектурное решение

`HabitTile` остаётся контейнером desktop-композиции, а `MiniHeatmap` — единственным источником 30-дневной сетки. Нельзя переделывать общий `HabitHeatmap` с 90-дневной детализацией под новый list-вариант, поскольку он остаётся самостоятельным компонентом полной истории.

### Необходимые изменения

1. В нижнем ряду `HabitTile` заменить вызов `HabitHeatmap` в `compact`-режиме на `MiniHeatmap` с существующими completion-данными, target и цветом привычки.
2. Сверстать нижнюю область для desktop-сетки и коротких подписей начала/конца периода согласно общему решению HLR-HEATMAP-01; сохранить безопасное пространство для completion-control.
3. На ширине desktop-карточки сохранить читаемость сетки, отсутствие обрезания и стабильное расположение title, tooltip, ring и кнопки выполнения.
4. Не менять `HabitHeatmap.svelte`, модель данных, streak/completion-rate расчёты, callback `onDetail` и `onToggle`.

### Вне области задачи

- Перевод dashboard целиком на одну плотность или изменение пользовательской настройки `viewDensity`.
- Редизайн карточек вне блока недавней активности.
- Изменение полноразмерного heatmap, страниц statistics и деталей привычки.
- Добавление desktop-only данных, API или persistence.

### Критерии приёмки

- При `viewDensity=comfortable` каждая плитка привычки содержит 30-дневную сетку, где последний день — сегодня, а выполненные дни окрашены темой привычки.
- Нельзя одновременно отобразить в плитке прежний 90-дневный `HabitHeatmap compact` и новый list-хитмап.
- На desktop viewport 1280 px в сетке из нескольких плиток хитмап остаётся внутри границ каждой плитки; кнопка выполнения имеет область не менее 44×44 px и доступна без наложения.
- Длинное название, описание, target больше 1 и momentum-индикатор не перекрывают хитмап, ring или кнопки.
- Клавиатурные переход и отметка привычки работают как до изменения.

## HLR-HEATMAP-03: Зафиксировать контракт данных и адаптивную геометрию хитмапа

**Status:** DONE
**Priority:** P2  
**Depends on:** HLR-HEATMAP-01, HLR-HEATMAP-02

**Точная область:**

Добавить направленные регрессионные тесты для `MiniHeatmap`, обновлённой compact-строки и desktop-плитки. Проверить через браузер фактическую геометрию обоих вариантов dashboard, а не подменять её успешной сборкой.

**Файлы:**

- Создать `apps/web/tests/unit/MiniHeatmap.test.ts`.
- Создать `apps/web/tests/unit/HabitCompactRowHeatmap.test.ts` для контракта mobile-встраивания.
- Создать `apps/web/tests/unit/HabitTileHeatmap.test.ts` для контракта desktop-встраивания.
- Изменить `apps/web/tests/e2e/habit-journey.spec.ts`, следуя существующей настройке Playwright и способу аутентифицированного seed-данных.
- Контекст: `apps/web/src/lib/components/MiniHeatmap.svelte` и `apps/web/src/lib/components/dashboard/HabitCompactRow.svelte`.

**Цель:**

Будущие изменения не должны незаметно сократить диапазон, сломать отображение выполнений или снова скрыть хитмап на мобильном экране.

### Результат

Тесты доказывают состав 30-дневной сетки и её привязку к completion-данным; browser E2E фиксирует отсутствие горизонтального overflow, доступность основных действий при узком mobile viewport и правильное размещение в нескольких desktop-плитках.

### Архитектурное решение

Unit-тест проверяет входные данные и DOM-компоненты без копирования логики дат. E2E переключает существующий dashboard между `compact` и `comfortable`, использует реальный тестовый путь создания/загрузки привычки и не вводит отдельный mock-only экран.

### Необходимые изменения

1. Написать unit-тест с фиксированной датой, который проверяет наличие 30 ячеек фактических календарных дат, корректные `data-lookup-key` и состояние complete/incomplete для привычки с `dailyTarget` больше единицы.
2. Написать тесты контрактов `HabitCompactRow` и `HabitTile`, подтверждающие постоянное использование `MiniHeatmap` без mobile-only скрытия и отсутствие прежнего `HabitHeatmap compact` в desktop-плитке; доступные элементы управления должны сохраняться.
3. Добавить Playwright-проверки dashboard: при viewport 320 px в compact-виде нет горизонтального overflow, а при viewport 1280 px в comfortable-виде хитмап виден в каждой тестовой плитке и не выходит за её границу; completion-control и переход к деталям доступны в обоих сценариях.
4. Запустить статические проверки, unit-тесты, production build и новый targeted E2E. Если локальный сервер или браузерная песочница не позволяет выполнить E2E, явно зафиксировать инфраструктурную блокировку отдельно от результатов unit/lint/build, не ослабляя сценарий.

### Вне области задачи

- Полная переработка всех существующих e2e-сценариев.
- Visual-regression сервис, скриншотный baseline или изменение глобальной Playwright-конфигурации без необходимости для этого сценария.
- Изменение backend-тестов или проверка remote CI/deployment.

### Критерии приёмки

- Unit-тест детерминированно доказывает 30 различных дней от «сегодня − 29» до «сегодня» и корректную окраску при целевом количестве больше одного.
- Unit-тест compact-строки предотвращает возврат condition/breakpoint, скрывающего `MiniHeatmap` на mobile; unit-тест плитки предотвращает возврат прежнего `HabitHeatmap compact` вместо 30-дневной сетки.
- В браузерном сценарии на 320 px нет горизонтального overflow; строка содержит хитмап, completion-control доступен по имени и привычка открывается обычным пользовательским действием.
- В браузерном сценарии на 1280 px каждая тестовая плитка comfortable-вида содержит хитмап в своих границах; кнопки выполнения и открытия деталей доступны.
- `npm run lint`, соответствующие unit-тесты и `npm run build` проходят без предупреждений, suppressions и новых исключений из правил качества.
